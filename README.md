# Защищённый REST API с интеграцией в CI/CD

Работа 1 по дисциплине «Информационная безопасность», Университет ИТМО.
Выполнил: **Зыонг Динь Ань**, группа **Р3414**.

Простой, но защищённый веб-API на **Python / Flask**, демонстрирующий базовые
меры защиты из **OWASP Top 10** и автоматическую проверку безопасности кода
в пайплайне **GitHub Actions** (SAST + SCA).

## 1. Описание проекта и API

API реализует мини-блог: пользователь регистрируется, входит и получает
JWT-токен, после чего может читать и создавать посты. Данные хранятся в
SQLite.

| Метод  | Эндпоинт         | Доступ            | Описание |
|--------|------------------|-------------------|----------|
| POST   | `/auth/register` | открытый          | Регистрация пользователя (пароль хэшируется bcrypt) |
| POST   | `/auth/login`    | открытый          | Аутентификация; возвращает JWT-токен |
| GET    | `/api/data`      | **только с токеном** | Список постов (защищённый эндпоинт) |
| POST   | `/api/posts`     | **только с токеном** | Создать пост (третий метод) |
| GET    | `/health`        | открытый          | Проверка работоспособности |

### Примеры вызовов (curl)

```bash
# 1. Регистрация
curl -s -X POST http://127.0.0.1:5000/auth/register \
  -H "Content-Type: application/json" \
  -d '{"username":"alice","password":"Secret12345"}'

# 2. Вход — получаем токен
TOKEN=$(curl -s -X POST http://127.0.0.1:5000/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"alice","password":"Secret12345"}' | python -c "import sys,json;print(json.load(sys.stdin)['token'])")

# 3. Доступ к защищённым данным (с токеном)
curl -s http://127.0.0.1:5000/api/data -H "Authorization: Bearer $TOKEN"

# 4. Доступ БЕЗ токена — будет отказано (401)
curl -s -i http://127.0.0.1:5000/api/data

# 5. Создание поста
curl -s -X POST http://127.0.0.1:5000/api/posts \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"title":"Привет","content":"Первый пост"}'
```

## 2. Подробное описание реализованных мер защиты

### 2.1. Защита от SQL-инъекций (A03:2021 Injection)

Все обращения к базе данных используют **параметризованные запросы**
(prepared statements): значения подставляются драйвером отдельно от текста
SQL и никогда не склеиваются со строкой запроса.

```python
# app.py — так делается ВЕЗДЕ в проекте
db.execute("SELECT password_hash FROM users WHERE username = ?", (username,))
```

Конкатенация строк для формирования SQL (`"... WHERE username='" + username + "'"`)
не используется нигде. Поэтому ввод вида `' OR '1'='1` воспринимается как
обычное значение логина и не меняет логику запроса (есть тест
`test_sqli_in_login_is_safe`).

### 2.2. Защита от XSS (Cross-Site Scripting)

Весь пользовательский текст, который может быть показан в браузере,
**экранируется** функцией `markupsafe.escape()` перед сохранением и выдачей.
Опасные символы (`<`, `>`, `&`, `"`) заменяются на HTML-сущности, поэтому
полезная нагрузка `<script>alert(1)</script>` превращается в безопасный
текст `&lt;script&gt;alert(1)&lt;/script&gt;` и не исполняется (тест
`test_xss_is_escaped`).

### 2.3. Защита от Broken Authentication (A07:2021)

* **Хэширование паролей.** Пароли никогда не хранятся в открытом виде —
  только в виде **bcrypt-хэша с солью** (`bcrypt.hashpw`). bcrypt —
  медленный адаптивный алгоритм, устойчивый к перебору, в отличие от
  быстрых SHA-256/MD5.
* **JWT-токены.** После успешного входа выдаётся подписанный **JWT**
  (алгоритм HS256) со сроком жизни 60 минут. Секрет подписи берётся из
  переменной окружения `JWT_SECRET` и **не хранится в репозитории**.
* **Middleware проверки.** Декоратор `@require_auth` проверяет токен на всех
  защищённых эндпоинтах; при отсутствии, истечении или подделке токена
  возвращается `401`.
* **Защита от перечисления пользователей.** При неверном логине и неверном
  пароле возвращается одинаковый ответ «Неверный логин или пароль».

## 3. CI/CD pipeline (GitHub Actions)

Файл конфигурации: [`.github/workflows/ci.yml`](.github/workflows/ci.yml).
Проверки запускаются **автоматически при каждом push и pull request**.

Pipeline выполняет три шага:

1. **SAST — Bandit** — статический анализ исходного кода Python на типовые
   уязвимости (небезопасные функции, хардкод секретов и т. п.).
2. **SCA — pip-audit** — анализ зависимостей из `requirements.txt` на
   известные уязвимости (CVE) по базе OSV/PyPI Advisory.
3. **Тесты** — `pytest` прогоняет функциональные тесты и тесты безопасности.

Отчёты Bandit и pip-audit сохраняются как артефакты запуска (раздел
**Actions → <запуск> → Artifacts → security-reports**).

## 4. Локальный запуск и тестирование

```bash
pip install -r requirements.txt
export JWT_SECRET=$(python -c "import secrets; print(secrets.token_urlsafe(48))")
python app.py          # запустит сервер на http://127.0.0.1:5000

# в другом терминале — тесты:
pip install pytest
pytest -q
```

Проверено: аутентификация работает, доступ к `/api/data` без токена
запрещён (`401`), SQLi и XSS нейтрализуются — все 5 тестов проходят.
